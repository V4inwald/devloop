# Fermer les trous durs et livrer le bundle installable

## Outcome

The kit can be installed into an existing repository without destroying files,
a branch cannot unlock its own push protection, CI runs on task branches with
`policy --strict`, and the installable skill is actually present in git.

## Acceptance criteria

- [x] AC1: `pre-push` ignores a repo-local `ALLOW_MAIN_PUSH`; the environment override still works.
- [x] AC2: `install.sh` refuses to overwrite kit files without `--force` (exit 4), preserves unknown hooks/workflow/scripts/LESSONS, backs up replaced files under `<git-common-dir>/devloop/backup-*`, installs the workflow as `devloop-ci.yml`, and writes neutral STATE/LESSONS templates on a fresh install.
- [x] AC3: CI triggers on `main` and `task/**`, runs `policy.sh --strict` on PR and push, uses actions v7 with `persist-credentials: false`, and has a job timeout.
- [x] AC4: the installable bundle is tracked in git and byte-identical to its source (`diff -r` checks in the review evidence); a fresh install works from a clean checkout.
- [x] AC5: `bash tests/run.sh` -> 90/0; `gate.sh` -> exit 0, `dirty:false`.

## Scope

Touched: `.githooks/pre-push`, `.github/workflows/ci.yml`,
`dist/devloop-skill/` (skill source + generated assets), `docs/STATE.template.md`,
`docs/LESSONS.template.md`, `tests/run.sh`, `docs/tasks/task-004.md`.

Out of scope: documentation alignment and team mode (task-005), GitHub branch
protection and PR mode (task-006), AC-as-code and mutation checks (task-007).

## Verification plan

1. `bash tests/run.sh` (90 assertions, including install safety and the
   pre-push bypass).
2. `bash scripts/devloop/gate.sh`.
3. Push the merge and watch the `ci` workflow on GitHub.

## Risks

- The bundle duplicates the source (`dist/devloop-skill/assets`). It is
  regenerated by `refresh.sh`; a CI drift check (`diff -r`) is still missing and
  belongs to task-006/007.
- GitHub Actions v7 is recent; the post-merge CI run is the real validation.
- The bundle import is oversized for `MAX_DIFF_LINES` because the skill was
  previously excluded from git by a local `.git/info/exclude`; the human
  delegated the order and the repository must ship the skill to be usable.

## Notes / decisions

- 2026-10-21: `dist/` was ignored via `.git/info/exclude` (local, not cloned),
  so the GitHub repository had no installable skill at all and the first CI run
  could not have exercised it. The bundle is now tracked; the include is
  verified byte-identical to the source for every mirrored path.
- The install safety tests run the real `dist/devloop-skill/install.sh` in two
  throwaway repositories (custom files, fresh clone) and assert both the refusal
  and the `--force` backup.
