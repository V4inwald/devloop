## Blockers

1. `scripts/devloop/doctor.sh:61-64` — the default store is `${GIT_COMMON_DIR}/devloop`, i.e. `$ROOT/.git/devloop` in the main worktree, which matches the `"$ROOT"/*` arm. Doctor therefore warns `artifact store ... is inside the worktree; upgrade the kit so a fresh clone cannot go dirty` on every normal repo (observed: this repo warns; a linked worktree prints `OK shared artifact store`), contradicting AC3/AC5 and the point of the move. Smallest fix: add a `"$GIT_COMMON_DIR"/*` (or `"$ROOT"/.git/*`) arm that prints `ok "shared artifact store ($ART)"` before the `"$ROOT"/*` arm, and keep the warning only for stores that are actually part of the worktree.
2. `scripts/devloop/doctor.sh:68-74` (and the else branch at `:103-113`) — legacy evidence is stored by existing installations in `$ROOT/.devloop/artifacts`, but doctor now reads only `$ART/integrations` and `$ART/gate`. Reproduced with an upgrade fixture (main merge commit, record `merge_sha`/`head_sha`/`reviewed_sha` + clean gate in the old store): the parent doctor exits 0 with `HEAD is an integration merge` / `integrated head has a passing clean gate result`; the reviewed doctor exits 1 with `no gate result for HEAD`. AC5 ("still accepts legacy integration records") and the task's Risks ("doctor must tolerate the old path and the old integration records") are therefore unmet for the scenario they describe. Smallest fix: when the shared store has no matching record/gate, look up the legacy store read-only (e.g. `LEGACY_ART="${DEVLOOP_LEGACY_ARTIFACTS:-$ROOT/.devloop/artifacts}"`) for the integration record and `gate/<sha>/result.json`, and emit an explicit legacy-evidence WARN when it is used.
3. `scripts/devloop/gate.sh:47-51` — `CHECK_*` commands are now executed with `bash -c` instead of the documented `eval` in the repository shell (`.devloop.conf.example:3`: "Commands run with `eval` from the repository root: treat this file as code"). A working config that defines a shell function (or relies on a non-exported conf variable) and uses it as a check now fails with exit 127 (verified: parent gate exit 0, reviewed gate exit 1 with `.checks[0].exit == 127`); the timeout wrapper is not required by task-001 and is not covered by any test. Smallest fix: restore `( eval "$cmd" )` and drop `GATE_TIMEOUT` from this change; if timeouts are wanted, land them as a separate task that preserves the documented contract and adds a function-valued check regression test.
4. `.github/workflows/ci.yml:35` — the "Upload gate evidence" step still reads `.devloop/artifacts/`, while the gate now writes `$GIT_COMMON_DIR/devloop` (`.git/devloop` on a CI checkout). The upload will find nothing and only emit a warning, silently removing the CI evidence artifact that the workflow exists to publish; `common.sh:24-25` even advertises `DEVLOOP_ARTIFACTS` for CI but the workflow never sets it. CI is listed as out of scope in the task file, but this is collateral damage from the path change. Smallest fix: set `DEVLOOP_ARTIFACTS: ${{ github.workspace }}/.devloop/artifacts` on the gate step (keeps the existing upload path), or point the upload at `.git/devloop` with `include-hidden-files: true`; if it is deliberately deferred, record the follow-up in the task file so CI evidence cannot be assumed to work.

## Verdict rationale

The core outcome is demonstrated: the store is shared under the git common directory, two clean gate runs leave no untracked file, the dirty run exits 3 without `PASSED`, and the new assertions genuinely fail on the parent scripts. The contract-file changes are not accepted as-is, so this round is `contract: n/a`; fix B1-B4 (or explicitly re-scope B4) and re-run gate plus a fresh review round.
