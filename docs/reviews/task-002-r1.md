## Blockers
1. `scripts/devloop/doctor.sh:102-112` and `:159-173` — the bookkeeping branch computes `EVIDENCE_SHA=HEAD^` but, when no integration record exists for that parent, falls through to the ordinary-evidence `else` instead of failing closed. Reproduced in `/tmp/docprobe`: fast-forward `main` to a gated+reviewed task tip (no `integrate.sh` run, no merge gate, no integration record), then commit `docs/STATE.md`; `doctor.sh` exits 0 with "HEAD is a bookkeeping commit", "passing clean gate result", "review file … covers HEAD". Doctor therefore certifies a `main` that bypassed the whole integration gate AC6 is supposed to preserve. Smallest fix: after `FOUND="$(find_integration "$EVIDENCE_SHA")"`, if `BOOKKEEPING=1` and `FOUND` is empty, `err "bookkeeping parent $EVIDENCE_SHA is not an integration merge"` and do not run the ordinary-evidence branch (guard it with `[ "$BOOKKEEPING" -eq 0 ]`); add the regression case to `tests/run.sh`.
2. `scripts/devloop/common.sh:14,17` + `scripts/devloop/integrate.sh:140-149` — `CONTRACT_PATHS` is seeded with the default and then `.devloop.conf` is sourced from the branch's working tree, so the branch under review can overwrite the list. Reproduced: appending `CONTRACT_PATHS=""` to `.devloop.conf` and sourcing `common.sh` yields `cp=[]`; `integrate.sh` then iterates zero paths, so a branch that edits `.devloop.conf` and `scripts/devloop/*` integrates with `contract: n/a`, violating AC3 (the task-014 test only covers the default config). Smallest fix: make the contract set a union of a non-overridable default and the configured paths (or read the config as of `$BASE`/`main` and union it with the defaults), then add a test where the branch edits `.devloop.conf` plus a script and the review omits `contract: approved`.
## Findings (non-blocking)

If `main` changed `gate.sh`/`common.sh` since `BASE`, the merge result is certified by the old harness; today `BASE == main`, so no drift. Consider invoking the merge tree's script after a minimal sanity check.
- AC4's failure path ("a failing merge gate leaves `main` untouched") has no test; it is only guaranteed by the ordering at `integrate.sh:205-218`. A check that fails only when two merged files coexist would cover it.
- `doctor.sh:60-78` (`review_covers`) is weaker than `integrate.sh`: no `task:` filter, tolerates `M docs/reviews/`, and does not require the review to postdate the reviewed SHA. This is the duplication already listed in the task Risks; a doctor-green HEAD is not proof that integrate would accept it.
- Two consecutive bookkeeping commits are not recognized (only `HEAD^` is tested for an integration record); the second one makes doctor error. Acceptable limitation, worth a note in the task or a loop.
- `integrate.sh:132` iterates in reverse lexicographic order, so `r9` is considered before `r10`; with two valid approvals the older blob can be pinned. Harmless today, but "latest review" is not actually selected.
- `--push` remains untested (declared in Risks) and a failed push dies after `main` has already moved locally (`integrate.sh:220-229`, `:250-252`); the message says so, which is acceptable.
## Verdict rationale
The merge machinery itself is sound and better than the old flow: `flock` serializes integrations (with a mkdir fallback), the merge is built and gated in a detached worktree, and only then is `main` fast-forwarded or moved with a compare-and-swap ref update, so a failed gate leaves `main` untouched. I accept the authorized `--allow-oversized` exception for this 563-line task: it is one coherent structural hardening, not a bloated feature, and the test diff strengthens rather than weakens coverage. It is not ready yet because the new evidence model has two holes — doctor certifies bookkeeping histories that never went through integration, and the contract approval can be disabled by the branch's own config — both small, testable fixes.
